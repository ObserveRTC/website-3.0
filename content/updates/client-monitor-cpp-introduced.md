## The first native release

Client Monitor C++ 0.1.0 is a C++17 port of the core of Client Monitor JS 4.11.0, producing ObserveRTC `ClientSample` records on schema 3.7.0. It gives native applications the same sample-based path toward backend analysis without running the JavaScript library.

## What is included

- `ClientMonitor` with a listener API, automatic collection or manual `Collect()`, sampling, client events, metadata, extension statistics, and issues.
- `PeerConnectionMonitor` and 15 statistics monitors covering RTP, ICE, codecs, media sources and playout, data channels, certificates, and tracks, with derived metrics.
- Five detectors: collection gaps, ICE disconnection, transport delay, and dry inbound and outbound tracks.
- `LibWebRtcStatsAdapter` and sample types generated by the ObserveRTC schemas project.
- Optional libwebrtc and libmediasoupclient bindings.

The release notes identify `observertc::clientmonitor` as the native namespace, alongside generated types in `observertc::schemas`. Native methods and listener interfaces differ from JavaScript event handling.

## Examples and API guidance

The release includes [an API guide](https://github.com/ObserveRTC/client-monitor-cpp/blob/v0.1.0/docs/USAGE.md) with recipes for public APIs and `examples/api_tour.cpp`, which the release notes describe as compiling and running in CI. Consume the source-built CMake library at tag `v0.1.0` and follow its binding configuration instructions.

## Check the integration limits

The optional libwebrtc and libmediasoupclient bindings have not yet been compiled against either dependency, according to the release notes. Verify compatibility with your native build rather than assuming it from the core tests.

Detector coverage remains partial. The default score calculator and MOS scoring are not ported; without a custom calculator, the client score stays at 5.0. Selected ICE path tracking and SDP monitoring are also not ported. See the tagged [porting status](https://github.com/ObserveRTC/client-monitor-cpp/blob/v0.1.0/PORTING.md) for the full scope.

Start with [Native C++ integration](/docs/client-monitor-js/native-cpp/) for the architecture and implementation boundaries.
